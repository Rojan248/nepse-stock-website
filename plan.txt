Making Your API Future-Proof (Without Official APIs)
Since paid APIs aren't an option, here are practical strategies to make your scraping more resilient:

1. Defensive Scraping with Validation
Instead of raw regex, add a "format check" layer that detects when HTML structure changes:

javascript
// Before parsing, validate expected structure exists
const expectedMarkers = ['Total Transactions', 'class="market-summary"'];
const missingMarkers = expectedMarkers.filter(m => !html.includes(m));
if (missingMarkers.length > 0) {
    logger.error(`Format changed! Missing: ${missingMarkers.join(', ')}`);
    // Alert you via webhook, fall back to cached data
}
2. Cache Last Known Good Data
Store the last successful response in the database. If all scrapers fail, serve stale data with a warning flag:

javascript
if (!freshData) {
    const cached = await getLastKnownData();
    return { ...cached, isStale: true, lastUpdated: cached.timestamp };
}
3. Multiple Source Redundancy (Already done!)
Your Promise.any() refactor already helps. Add new sources as they become available.

4. Monitoring & Alerts
Your alertService.js exists but isn't active. Enable Discord/Slack webhooks to get notified when scrapers fail:

env
WEBHOOK_URL=https://discord.com/api/webhooks/xxx/yyy
ALERT_ENABLED=true
5. Use nepse-api-helper as Primary
This library wraps the unofficial NEPSE API and is maintained by the community. It's your most stable source. Keep it updated:

bash
npm update nepse-api-helper
